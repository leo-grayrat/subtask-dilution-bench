# 研究总账

更新日期：2026-08-24

这份文件只负责防止项目在新搜索、新案例和新实现之间反复改题。它不是题库、资料汇总或实施计划。

任何新工作开始前，先回答：它属于哪条研究线、补哪个证据缺口、保留哪些既有决定、是否正在把辅助材料偷偷变成新的研究中心。

## 1. 最初观察与研究边界

项目起点是一个行为层面的怀疑：

> 模型完成复杂整体任务时，一些单独有能力处理的局部问题，可能没有真正进入判断；整体仍能交付，局部却出现不必要的粗糙处理、遗漏或错误。

最初案例包括自然语言字段被机械转成字符数、复杂图像中的局部细节失守，以及长对话里仍记得若干标签却没有保留标签之间的理由关系。

这些案例只能说明值得研究，不能直接推出：

- 三个案例属于同一种机制；
- 内部原因一定是“注意力”或“思考资源被摊薄”；
- 字符串、Markdown、审批规则就是未来题型；
- 只要局部版本更复杂，就比完整任务中的轻量方案更好。

实验首先证明可观察的行为差异，再讨论机制。

## 2. 三条独立研究线

### 2.1 子任务稀释

研究完整复杂任务中自然产生的局部决定，是否会因任务组织、竞争目标或实际投入不足而退化。

主实验是同一完整状态的 `direct / sham / reconsider` 中途分叉。它不以固定规则题或孤立小题为主体。

### 2.2 显著反馈导致资源失衡

研究某个局部目标因为反馈特别连续、清晰、容易优化，是否获得了超过其全局价值的投入，并挤压更重要但反馈较弱的工作。

主实验是“反馈强弱 × 局部价值高低”的 2×2 对照。它不要求模型违反规则或作弊。

### 2.3 上下文不参与决策

研究模型能找到规则、知道规则是否适用于当前事实、单独也能执行，却在完整工作流里没有让规则约束实际动作的情况。

主诊断是 `Recall / Applicability / Local Execution / Full Execution` 四层独立测试，并配合规则生效与不生效的反事实状态。

三条线可以共享部分打包、运行记录和统计工具，但不能共享一个总分，也不能用一条线的样本替代另一条线的证据。

## 3. 不得静默推翻的原则

1. 不让 AI 从空白开始批量编造世界、规则和语义陷阱。
2. 不把换公司、人名、金额、日期或行业外皮当作范式多样性。
3. 不把多个条件包、多个中间位置或多次随机运行冒充独立母任务。
4. 不因孤立局部版本更细致，就直接判定完整任务版本退化。
5. 合理简化允许保留；只增加篇幅、复杂度或工具调用不算改善。
6. 被测模型的自我反思只能产生候选，不能担任自己的裁判。
7. 硬错误和软性“没想透”分别报告，不强行压成一个神奇总分。
8. 在子任务稀释主实验中，错误位置和错误形态应尽量保持未知；不能看见目标模型犯错后再挑检查点。上下文整合与反馈分配本来就预先冻结目标规则或焦点目标，不套用这条未知位置要求。
9. 先用小规模实验验证现象和测量方法；没有信号就停止，不用扩题掩盖失败。
10. 现成 benchmark 首先提供真实任务分布、材料、环境和评分器，不是供我们拼成杂题卷的小题库。
11. 搜索结果只能填补已经写明的缺口；不能因为新来源很有趣就改变研究问题。
12. 每条结论必须与实际证据同宽，工程测试通过不能写成模型行为已经得到验证。

## 4. 现有成果的位置

### 4.1 已保留的子任务稀释设计

`docs/subtask-dilution/` 已经固定了：真实完整任务、事先确定的 checkpoint、`direct / sham / reconsider`、硬软双轨评价，以及无信号不扩题库。

这仍是原始子任务稀释问题的主架构。目前尚未完成真实 checkpoint pilot。

### 4.2 已实现的上下文整合任务族

仓库现有七个基础任务族：S01、S02、S04、S07、S08、S09、S10。已有资产包括：

- 从真实 HANDBOOK 工作区生成任务；
- 局部与完整版本；
- 规则生效与不生效版本；
- 程序化评分；
- 匿名导出和私下条件对应表；
- 泄漏检查、质量审计和候选淘汰记录。

第二批统一命令会从六个母任务生成 24 个条件包。加上 S01 后，代码库中共有七个母任务、每个可表达四种基础条件；它们不是 28 个独立样本。

这些工程资产证明任务可以生成、评分和匿名发布，不证明目标模型已经表现出上下文整合失败。

当前发布流程只有 `local/full × active/inactive`。它还没有实现四层诊断中的 Recall 和 Applicability，因此在补齐前只能声称“可测局部与完整执行差异”，不能声称已经证明“模型记得且理解，却没有使用”。

25 个 HANDBOOK 条目是候选池，不是正式样本量，也不是整个项目的代表性来源。暂不继续扩池。

### 4.3 已设计但未实现的反馈分配实验

`docs/feedback-allocation/` 已经固定 2×2 核心对照、固定预算、局部投入与全局机会成本，并把“同一信息的呈现显著性”和“连续在线反馈”拆成 P/C 两个独立模块。v0 的价值操纵是明确进入 evaluator 的受控权重，不冒充现实世界的自然价值。该方向保留，但目前没有 runnable pilot。

### 4.4 可以复用但不改变问题的工程

匿名命名、私下 mapping、校验值、生成器接口、评分器测试和实验产物目录可以被其他研究线借用。复用这些工具不代表三条研究线使用同一任务或同一指标。

## 5. 已放弃或降级的路线

| 路线 | 处理 | 原因 |
| --- | --- | --- |
| 批量生成一百个虚构项目 | 放弃 | 容易用不同故事重复同一逻辑骨架 |
| 把不同 benchmark 小题拼成大杂题 | 放弃 | 测到多题答题，不像服务同一目标的复杂工作 |
| 用 `solo > whole` 直接证明稀释 | 降为诊断 | 两种范围下的合理资源配置不同 |
| 继续把 HANDBOOK 候选从 25 扩到更多 | 暂停 | 数量不能解决抽样框和范式代表性 |
| 只依赖模型自我批评 | 放弃 | 迎合提示且倾向制造更复杂答案 |
| 只看自动硬分 | 放弃作为完整研究 | 会删掉最初关心的软性局部退化 |
| 只做事后人工挑错 | 降为发现通道 | 存在选择偏差，不能单独给出因果证据 |
| 为了一个统一故事合并三条研究线 | 放弃 | 三种行为的原因、操纵和指标不同 |

## 6. 尚未解决的证据缺口

### 跨项目缺口

- 被测智能体如何与实验仓库、评分器和主对话真正隔离；
- 运行配置、模型版本、随机性和预算如何冻结；
- 如何按母任务归组分析多位置、多条件和多次运行；
- 如何保存原始轨迹、产物和评分证据，同时不向被测模型泄漏实验目的。

### 子任务稀释

- checkpoint、分叉备选、盲评和母任务抽样框已经形成测试前规格，但尚未实现和用练习任务验证；
- 具体母任务 ID、平台实际可用的状态复制方式、原生 evaluator 门槛和人工评审安排尚未冻结；
- 尚未完成任何真实 checkpoint pilot，因此没有模型行为结果。

### 上下文不参与决策

- Recall 与 Applicability 两层任务的生成、评分和匿名运行尚未落地；
- 每个可运行条件 5 次独立重复已经写入规格，但成本与隔离可行性尚未验证；
- 隔离问题解决前不能开展正式模型实验；
- HANDBOOK 之外的验证只有在 v0 出现信号后才有必要。

### 显著反馈导致资源失衡

- 第一个可严格控制反馈显著性、又有两个竞争目标的真实环境尚未冻结；
- P/C 两个反馈模块、受控外部价值、投入和机会成本已形成规格，但尚未实现和通过练习任务预检；
- 正式母任务、备用顺序、预算、反馈呈现器与动作标注实现尚未冻结；
- 原生任务价值只作为以后外部验证，不能与 v0 的受控 3:1 权重混成同一结论。

## 7. 证据与可声称结论

| 证据 | 可以支持 | 不能支持 |
| --- | --- | --- |
| 生成、评分和匿名包测试通过 | 工程流程可运行、答案未直接泄漏 | 模型行为现象存在 |
| 同一母任务多个条件和重复运行 | 条件内稳定性与因果敏感性 | 更大的任务总体代表性 |
| `Local > Full` | 在该任务上存在执行范围差异 | 内部原因一定是注意力不足 |
| Recall、Applicability、Local 均通过而 Full 失败 | 该局部符合“知道但完整执行没用上”的诊断模式 | 所有上下文失败都属于这一机制 |
| Reconsider 优于 Direct 且超过 Sham | 少量定向重新审视在这些任务上有额外作用 | 自然环境中的普遍失败率 |
| 多个母任务方向一致 | 现象跨这些任务族出现 | 对所有领域和模型普遍成立 |

## 8. 新工作准入

新增搜索、样本、实现或指标前，必须在提交说明或设计记录中回答：

1. 属于哪条研究线？
2. 补的是第 6 节哪一个缺口？
3. 保留了第 3 节哪些原则？
4. 是否修改既有决定？若修改，明确写出被替代的决定和证据。
5. 新来源扮演的是材料、环境、评分器、控制组还是外部验证？
6. 如果不做这项工作，当前实验为什么不能回答目标问题？

答不清楚时，不开始工作。

## 9. 决策记录

### 2026-08-24：恢复旧主架构并保留现有资产

- 保留三条研究线和各自指标，不建立统一总分。
- 保留七个 HANDBOOK 母任务及其生成、评分、匿名发布工具。
- 停止继续扩充 HANDBOOK 候选池，把它定位为上下文整合 v0。
- 恢复真实完整任务中的 checkpoint fork 作为子任务稀释主实验。
- 将“多原生检查点、多角度变化、多次运行”定位为任务来源和统计层，不设为第四条研究线。
- 先完成三条设计的边界对齐；此后每条线只要独立通过自己的测试前门槛，就可以单独实现和运行，不等待另外两条线，也不能拿另一条线的完成度替它放行。

### 2026-08-24：明确两个不应混淆的缩窄

- 子任务稀释第一轮同时报告 direct 自然基线和 `reconsider - sham` 干预效应；后者不能冒充自然发生率或孤立任务能力。
- 反馈分配保留 P（同一信息的呈现显著性）与 C（连续在线 vs 批量延后）两个模块；一个模块的阴性结果不能否定另一个。
- 反馈 v0 使用明确、外部执行的受控评分权重；现实任务中的原生价值留作独立外部验证。
