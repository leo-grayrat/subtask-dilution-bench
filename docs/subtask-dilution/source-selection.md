# 子任务稀释：参考 benchmark 与素材选择

## 1. 现成 benchmark 的角色

我们不打算让 GPT 批量生成一百个“项目”。现成 benchmark 最重要的价值是提供：

- 人类已经整理过的真实材料和任务分布；
- 比较自然的完整工作目标；
- 部分已有 gold answer、测试或 evaluator；
- 跨领域多样性。

我们真正新增的是**运行和对照协议**，而不是重新编一个世界。

## 2. 选择标准

候选任务优先满足：

1. 本身就是一个需要持续工作的完整任务，而不是只有最终一个选择题答案；
2. 运行过程中会自然产生多个局部判断；
3. 某个局部做差以后，整体任务仍可能继续完成，不会立刻被强反馈强制修正；
4. 至少一部分结果有外部可检查依据；
5. 可以在不改变整体目标的前提下做 checkpoint fork；
6. 不需要我们先知道“模型最可能在哪里犯错”。

第一版不做图像生成实验：成本高、评价难，而且容易引入新的视觉 evaluator 问题。

## 3. 当前优先参考的来源

这些都是**素材来源候选，不是已经决定整套照搬**。下一步仍需抽真实样例逐条核验。

### GAIA

用途：优先寻找比较接近真实 assistant / agent 工作的完整任务，尤其是带文件、资料、工具使用和多步处理的实例。

适合借：真实任务形态、附件和较明确的最终答案 / 验证。

注意：有些实例的局部过程并没有天然 evaluator，需要配合 checkpoint 分支和人工盲审。

参考：
- https://arxiv.org/abs/2311.12983
- https://huggingface.co/datasets/gaia-benchmark/GAIA

### LongBench v2

用途：提供真实长文档、多文档、长对话、代码仓库、结构化数据等长上下文材料。

适合借：背景材料、隐藏事实检查和长上下文压力。

注意：原始任务很多仍是问答形式，不应直接把几道题拼成“项目”；它更适合作为材料池和 hard probe 来源。

参考：
- https://github.com/THUDM/LongBench
- https://arxiv.org/abs/2412.15204

### LiveBench

用途：提供有客观 ground truth、较少依赖 LLM judge 的任务，尤其可关注 data analysis、instruction following 等部分。

适合借：硬评分、对照任务和已有 evaluator。

注意：单题本身往往不够像真实复杂项目，不作为主要生态场景来源。

参考：
- https://github.com/LiveBench/LiveBench

### SWE-bench

用途：提供真实 repository / issue 级工程任务，适合以后验证 checkpoint-fork 是否也会出现在长链代码工作中。

适合借：真实 repo、issue、测试和最终工程评价。

注意：代码测试、CI 等即时反馈很强，可能把局部错误“洗掉”，也会与“显著反馈导致资源失衡”方向发生混杂。因此不建议作为子任务稀释第一版唯一主场景。

参考：
- https://www.swebench.com/
- https://arxiv.org/abs/2310.06770

### BIG-bench / lm-evaluation-harness

用途：补充任务类型和学科多样性，或做基础能力 / 原子能力控制。

适合借：题型分布、现成实现和基础能力校准。

注意：多数原子题不适合直接当主实验；不要通过“把很多不同学科小题一起塞进去”制造所谓复杂任务。

参考：
- https://github.com/google/BIG-bench
- https://github.com/EleutherAI/lm-evaluation-harness

## 4. 暂不优先的材料

### 纯多要求指令

它们可以验证“要求越多，遵守率会不会掉”，但很容易退化成格式约束堆叠，和真实项目里的局部判断仍有距离。可以做控制，不作为唯一主证据。

### 只有最终答案的 QA / 数学题

它们适合确认某个模型原子能力，但很难观察“整体仍完成、内部局部已经失守”。

### 强即时反馈的代码环境

不是永久排除，而是第一版要谨慎，因为反复测试可能把我们最想观察的局部失误强制修正。

## 5. 下一步筛选方式

对每个候选 benchmark 抽少量真实实例，记录：

- 原任务是什么；
- 需要持续做多久、会产生哪些自然决策；
- 可以在哪里按统一规则设 checkpoint；
- hard evaluator 能覆盖什么；
- 哪些部分只能盲审；
- 是否存在过强即时反馈；
- 是否适合 direct / sham / reconsider 三分支。

先完成小规模 pilot，再决定正式数据集。
