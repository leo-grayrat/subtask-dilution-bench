# 子任务稀释：实验设计

## 1. 研究问题

我们想测的不是“复杂任务里的每个局部都应该做到和单独拿出来一样精致”，而是：

> **一个模型本来有能力处理好的局部问题，在进入更大的完整任务后，是否会因为实际认知投入不足、任务组织或信息保持等原因而出现退化？**

这里的 `thinking / attention / resource dilution` 都只是现象层面的解释。实验不能先假定内部机制就是“思考资源被平均摊薄”。

## 2. 已经固定下来的认识

### 2.1 不能把“更复杂”当成“更好”

单独处理一个局部问题时，模型天然会投入更多篇幅和计算。大任务里选择更轻量的方法可能完全合理。

因此我们不比较“谁更豪华”，而关注：

- 这个局部是否真的被理解和判断过；
- 是否存在成本相近、明显更符合整体目标的替代方案；
- 局部处理有没有破坏最终任务。

`description` 被拿去数字符只是发现问题的案例，不是题型模板。

### 2.2 不预先规定错误长什么样

如果先总结“字符串容易乱处理”“某类统计量容易选错”，再围绕这些坑出题，benchmark 很容易过拟合到已知失败。

第一轮更重要的是让模型完成真实复杂任务，再从任务原本就存在的决策里观察退化。

### 2.3 不把模型自我反思当 evaluator

不能在事后问同一个模型“刚才这个子模块有没有更好的办法”，再把它的自我批评当判据。模型会顺着质疑给出更复杂的替代方案，也容易产生迎合。

独立 replay 可以用于产生候选对照，但主判据必须来自外部 evaluator 或盲审。

### 2.4 “单独小任务”只适合做诊断，不再作为主实验

把一个局部完全孤立出来，会改变合理的资源分配：本来只值得轻量处理的部分，在孤立条件下自然会被做得更深。

因此主实验不再依赖“solo > whole-task”来证明稀释。

## 3. 主实验：完整任务中的 checkpoint fork

使用本来就完整、真实的复杂任务。模型从头到尾都知道最终目标、约束和剩余工作。

在运行前按统一规则选定若干 checkpoint；checkpoint 的选择不能依赖“我们已经看到这里犯错了”。到 checkpoint 后复制当前完整状态，分出三条支路：

### Direct

不增加提示，直接继续完成原任务。

### Sham

给予与 reconsider 分支相近的额外预算，但不提示具体局部是否有问题。它用于控制“只是因为多给了 token / 时间，所以结果更好”。

### Reconsider

仍保留完整任务上下文和总体预算，只给一个泛化的局部检查机会，例如：

> 针对你当前准备采取的步骤，检查是否存在成本相近但更符合最终目标的处理；如果原方案已经合适，就保持不变。

提示不能暴露我们怀疑的错误类型，也不能点名字段、约束或正确答案。

三条支路随后都继续完成同一个原任务。

## 4. 为什么这个对照更公平

它不会把一个普通局部突然升级成“无限资源的小型研究项目”。

如果原方案本来就是合理简化，reconsider 分支完全可以保持不变；如果 reconsider 只是增加复杂度而没有实质收益，也不算改善。

真正有价值的情况是：只给很有限的重新审视机会，模型就发现了原先一个成本相近却明显更差的局部决定，而且最终任务因此改善。

## 5. 评价

硬指标和软退化并存，但不硬合成一个总分。

### 5.1 Hard degradation

尽量继承现成 benchmark 的外部 evaluator，例如：

- 事实 / 条件是否错误；
- 必要要求是否遗漏；
- 计算或测试是否失败；
- 最终任务指标是否下降；
- 明确约束是否被破坏。

### 5.2 Soft local degradation

保留我们最初关心的“没有客观报错，但明显没有想透”。

对完整任务背景和两条匿名支路做盲评，只判断：

- 是否存在实质性局部改善；
- 是否只是增加复杂度 / 篇幅；
- 是否无明显区别。

评审必须看到完整任务和全局成本，避免天然偏爱更复杂的局部方案。

## 6. 主要分析

第一轮先回答：

1. reconsider 是否比 direct 更常产生实质性局部改变；
2. 这种改善是否超过 sham 所能解释的“多一点预算”效应；
3. 改善是否能传导到最终任务，而不是只让局部更花哨；
4. 自然出现的软失败到底有哪些形态。

如果 pilot 没有稳定信号，不继续扩成大题库。

## 7. 与另外两个方向的边界

- **显著反馈导致资源失衡**：研究某个有红绿灯/连续分数的局部目标是否吸走过多资源；单独开发。
- **上下文不参与决策**：研究模型明明能回忆约束、也理解动作，却在执行时没把两者结合；单独开发。

这三个方向可以在讨论层面互相解释，但不要共享一个总分或强行使用同一套题。
