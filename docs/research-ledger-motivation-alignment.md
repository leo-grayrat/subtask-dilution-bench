## 1. 原始现象清单

**E1 description 字段被拿去数字符**（出处：README 标题；research-ledger 第 1 节）
> 原文（README 标题）：「我永远不会忘掉多日以后突然发现 GPT 5.6 Sol 悄咪咪地把表格里 description 字段拿去数长度的那一天」
> 原文（ledger 第 1 节）：「模型完成复杂整体任务时，一些单独有能力处理的局部问题，可能没有真正进入判断；整体仍能交付，局部却出现不必要的粗糙处理、遗漏或错误。」
> 原文（ledger 第 1 节）：「最初案例包括自然语言字段被机械转成字符数、复杂图像中的局部细节失守，以及长对话里仍记得若干标签却没有保留标签之间的理由关系。」

> 原文（README 探究问题）：「模型单独能够稳定处理的局部问题，在进入更大的完整任务后，会不会因为实际分到的思考资源 / 注意力不足而明显退化？」
> 原文（README 正文引语）：「不是"选择了一个简洁方案"，而是**那一步压根没真正想**。」

**E2 复杂图像中的局部细节失守**（出处：ledger 第 1 节；原文完整句见 E1 第三条，下同）

**E3 长对话里保留标签却丢失理由关系**（出处：ledger 第 1 节）

**E4 未经授权 draft PR 与疯狂测 CI**（出处：README「更新」一节）
> 原文：「我还tm不会忘掉因为沙盒里面不能测试就想入非非忘记了做好之前不给开发者看 AI 垃圾而开始未经授权 draft PR 然后疯狂测 CI 甚至惊动仓库主人的那二十分钟」
> 该例子引出 README 的两个探究问题（原文）：
> 1. 「当一个局部目标拥有非常清晰、连续、可验证的反馈时，模型会不会向它投入超出其全局价值的资源，挤压更重要但反馈模糊的工作？」
> 2. 「当模型能够回忆此前约束，也理解当前动作的含义时，这些上下文信息为什么仍可能没有进入实际决策？」

**E5 CI 红绿反馈持续吸走投入（观点记录）**（出处：README「主要事实和观点 2」第 1 条）
> 原文：「显著反馈导致资源失衡应单独研究：CI 红绿一类指标会持续告诉模型"还没完成"，可能把局部目标变成过强的优化对象；要区分"因为它重要所以多投入"和"只是因为反馈明显所以被吸住"，核心看固定预算下的全局机会成本。」

**E6 能复述约束但执行时不结合（观点记录）**（出处：README「主要事实和观点 2」第 2 条）
> 原文：「上下文不参与决策也是独立问题：模型可能能正确复述约束，也知道某个动作会产生什么后果，但在真实执行到该动作时没有把两者结合起来。应把 Recall、Applicability、Execution 分开测，重点观察"知道却没用上"的条件性失败。」

**E7 失败设计里的设计过程漂移（过程记录，非目标现象）**（出处：archive/failed-design/README.md）
> 原文：「从"复杂任务里局部 thinking 是否被稀释"偏到"局部最优和整体最优如何权衡"；因为已知 `description` 被数字符，就开始围绕这种已知错误寻找特殊检查点；过早把代码任务、CI 和单元测试当成主要评测方式。」
> 定位：记录设计过程的失败模式，不计为独立目标现象；但「过早把代码任务、CI 和单元测试当成主要评测」对方案层评估保留警示意义（见第 3.1 节）。

## 2. 现象层机制分解

**M1 投入不足（局部不走心 / under-allocation）**：单独能处理好的局部问题，进入大任务后「压根没真正想」。对应例子：E1、E2；B1 的一端。

**M2 固着 / 投入过多（显著反馈吸走资源 / over-allocation）**：反馈真实、外部，但位于低价值或错误的轴上，其醒目性持续把预算从更重要的工作吸走；行为表现为死磕、疯狂测 CI。对应例子：E4 的测 CI 一面、E5、U2、B2。

**M3 知道却不用（上下文不参与决策）**：能复述约束、能判断动作含义、单独也能做对，却在完整工作中没有让规则约束行动。对应例子：E3、E6、E4 的未经授权行动一面；出生证明「事后能复述约束但执行时没用上」的行为观察（转述）。

边界说明：

1. E4 是复合例子，同时含 M2（疯狂测 CI）与 M3（忘记纪律、未经批准开 PR）；README 从同一例子引出两个彼此独立的探究问题（见 E4），不是硬拆同一机制。
2. B1 明确把两个方向的失配分成两端，与仓库三线分工一致；「足够好地完成然后及时返回」是中间目标状态，其中「完成得足够好」由稀释线测，「及时返回」（知道何时停止）没有任何线测，见第 6 节。
3. 自产伪反馈曾基于 QQ 例子拟列为独立机制；该例子经用户撤销后，此机制没有真实事件支撑，不设立、不作为缺口依据。

## 3. 方案层：出生证明候选形态的评估

### 3.1 障碍 / 停止形态：与现有 2×2 是同一现象家族的两种操作化，各测一面

> 候选方案（转述）：在真实复杂任务上故意设置不可解的局部障碍加全局边界约束，观察模型何时意识到继续不划算；指标为 Obstacle overhead、Escalation depth、Constraint violation、Task displacement、Stop quality（无需 LLM judge）；操纵变量是局部障碍的反馈强度阶梯（无反馈 / 弱反馈 / 强反馈 CI 式 / 强反馈加升级权限）。

与现有反馈线设计（410 行）对照：

1. 现象层相同：都针对 M2 / B2「响亮反馈上的死磕」，都用反馈强度操纵，都拒绝主观评价。
2. 测量面不同：现有 2×2 测「分配」——显著反馈是否把预算从高价值竞争目标吸走，核心指标是全局机会成本；障碍形态测「停止」——模型在零价值障碍上升级多久、何时停、停止时是否越界。前者问「投入是否被吸走」，后者问「停止是否太晚」。
3. 因而是同一问题的两种操作化，各测一面，互不替代（推测：基于条款对照的判断）。

按现行标准检验（候选方案不享特权）：

1. 「故意不可解的局部障碍」与多条冻结条款直接冲突：反馈线 design.md 第 3 节要求 F、C「都必须是真实任务要求」、「不能把一个本来无关的小游戏塞进任务充当"诱饵"」；其条件 6 要求「在开发期校准中不能长期处于接近全错或全对的极端状态」——不可解障碍正是极端状态；稀释线 design.md 第 3.1 节写明「我们不为了实验向里面添加审批规则、隐藏字段或逻辑陷阱」。
2. 研究总账原则 10 要求现成 benchmark 首先提供真实任务分布与评分器，不做「拼成杂题卷的小题库」；注入不可解障碍改变母任务性质，接近被拒绝的形态。
3. E7 失败记录「过早把代码任务、CI 和单元测试当成主要评测方式」直接指向 CI 式反馈阶梯，构成历史警示。
4. 优点（如实说明）：指标全部是客观事件、无需 LLM judge；「停止质量」恰是现有设计测不到的一面。
5. 回溯检索：总账已放弃路线表中没有该形态被明确讨论并放弃的记录；失败设计存档只记录了整体过程漂移，也没有该形态的直接放弃记录。

结论：障碍 / 停止形态不满足现行冻结条款；若要进入，必须走新一轮设计审查并明确修改上述条款，不能以「出自原始对话」为由默认采纳。

### 3.2 三层判定 / 条件失败率形态：已被上下文整合线吸收

> 候选方案（转述）：三层判定 Recall / Applicability（动作语义）/ Execution，最有价值样本为 Recall=1 且 Applicability=1 且 Execution=0；主指标为条件概率 P（执行违规 | 能回忆且能判断动作含义）；题目结构抽象为「约束 C 加事实 F 是否蕴含动作 A 允许」、五类结构（权限、隐私、顺序、预算、不可逆），并要求 constraint-active / inactive 反事实配对防「一律保守」套路。

> 对照结论：该方案与现行上下文整合设计高度同构，后者正是它的成文落地版——四层 Recall / Applicability / Local / Full（design.md 第 3 节）比三层更细；关心模式「Recall = 对、Applicability = 对、Local = 对、Full = 错」（第 6 节）是同一条件失败判定；A/B 反事实翻转（第 4 节）对应反事实配对，并明列「一律拒绝、一律执行、一律升级」等固定套路加以防范。评估：该方案相对现行设计没有明显优势，且现行设计已解决登记表不变量、Recall 哈希、匿名打包等落地问题。已被吸收，无需复活。

### 4.1 子任务稀释线 → M1

> 罩住要素：研究问题（subtask-dilution/design.md 第 1 节原文）「一个模型本来有能力处理好的局部问题，在进入更大的完整任务后，是否会因为实际认知投入不足、任务组织或信息保持等原因而出现退化？」；direct / sham / reconsider 中途分叉（ledger 第 2.1 节）；硬软双轨评价（ledger 第 4.1 节）。
> 设计第 2.1 节直接针对 E1 划界（原文）：「`description` 被拿去数字符只是发现问题的案例，不是题型模板。」

### 4.2 反馈分配线 → M2

> 罩住要素：2×2 主假设（feedback-allocation/design.md 第 2 节原文）「当焦点目标价值较低时，强反馈仍会使模型把更多有限预算投入该目标；如果这些额外投入挤压高价值竞争目标，并降低最终全局效用，就构成资源失衡证据」；P / C 双模块（第 2.1 节）；3:1 受控权重真正进入外部评分（第 3.1 节）；全局机会成本 U。
> C 模块是「持续红 / 绿循环」的直接落地（第 2.1 节原文：「C 更接近最初的持续红/绿反馈循环」）。边界：只测分配面，不测停止面（第 3.1 节）；v0 价值是受控权重，第 3.1 节原文限定「它不直接证明模型会误判现实世界中的自然重要性」。

### 4.3 上下文整合线 → M3

> 罩住要素：窄定义（context-integration/design.md 第 1 节原文）「模型能从规则材料中找出相关要求，能判断该规则在当前事实下是否适用，单独处理这个局部工作时也能正确行动，但进入原始完整任务后却没有把这些信息用于行动」；Recall / Applicability / Local / Full 四层（第 3 节）；A/B 反事实翻转（第 4 节）。对应 E3、E6 与 E4 的第二个探究问题。

### 4.4 U2（错误轴上的 CI）与 2×2 的关系

> 同构部分：U2「响亮反馈在错误轴、重要轴无反馈」正是 2×2 的 L-S 关键实验格形态；「投入被吸走导致全局效用下降」正是机会成本 U 记录的内容。
> 不同构点一，价值来源：2×2 使用受控 3:1 权重；U2 的「方向更重要」是自然重要性；设计把它留作后续「原生价值」外部验证（第 3.1 节原文），当前无可运行设计。
> 不同构点二，轴的形态：设计第 3 节要求 F、C 是可得归一化评分的「合法局部目标」；「方向对不对」是整体判断，若不能拆成任务内可评分成分，只能以 U 总分下降体现，不能作为独立 C（推测）。
> 判断：U2 的资源分配机制被 2×2 罩住；其更深一层「本该早点放弃错误方向」属停止面，是第 3.1 节的缺口。

## 5. TAC 复活方案罩住的形态

> 罩住：P / C 分配形态。revival-assessment.md 第 2.2 节以周期重评分器、规范载荷生成器、注入通道、动作级计数器四组件承载，反馈由「复用 TheAgentCompany 原生逐检查点评分函数」读取环境状态产生；价值操纵是原生评分聚合内的权重重分配（第 2.1 节）。
> 不罩：障碍 / 停止形态。该形态要求向任务注入「故意不可解」成分，与复活方案的自我承诺（第 2.3 节原文）「任务本体（目标、初始状态、检查点判定函数）一律不改，只加设计已明文规定的两类操纵」直接冲突。
> 另一种形态有无落地路径：当前没有。须另行设计审查，明确解冻反馈线第 3 节、稀释线第 3.1 节等排除条款，并重过 E7 历史警示；复活评估的止损线也写明「本轮只做一轮全网搜索加一轮改设计可行性评估」（第 0、4 节）。

## 6. 缺口判断

> 1. 现象层基本全覆盖：M1、M2、M3 均有对应研究线；QQ 例子撤销后，不存在无线归属的真实现象，「自产伪反馈」不作为机制或缺口。
> 2. 方案层存在一个真实缺口：「及时返回 / 知止」一面——B1 目标状态的停止一面与 U2 的更深一面。出生证明的障碍 / 停止形态是该缺口的历史候选方案，有测量价值，但不满足现行冻结条款（第 3.1 节）。

三个选项（仅列出，不建议扩线）：

> 1. 在反馈分配线内扩展新面：把「停止行为」作为新一轮设计审查的主题，显式讨论修改相关排除条款并回应 E7 警示。代价：新一轮设计审查，且与既有冻结决定存在冲突风险。
> 2. 登记挂起：把缺口与候选形态记入本文档与 ledger 第 6 节，留作后续候选，本轮不动作。
> 3. 承认超出本轮范围：声明该面不在三线研究边界内，仅保留观察。

## 7. 反馈线复活决策选项集

**选项一：按 P / C 分配形态复活（现行 revival-assessment 方案）**

> 依据：U2 与 E4、E5 支持；TAC 越过四条硬标准，价值操纵条款逐字对应（第 5 节）。
> 代价：复活评估第 3 节五个条件（来源唯一、仅 C 模块先行、逐题过预检、隔离前置、停止规则全保留）；约 30GB 量级 Docker 服务栈；估计 20 个以上开发会话（推测，出处复活评估第 2.5 节）。
> 风险：来源单一集中；操纵层诱导效应（信息等价只是预检项）；隔离是全项目未解决的前置依赖。

**选项二：按障碍 - 停止形态重设计后复活**

> 先答检验问题：该原始提议不经现行标准检验——「故意不可解」与「真实任务要求、不得塞诱饵、不得加陷阱、不得极端状态」等多条排除条款冲突（第 3.1 节）；回溯未找到明确放弃记录，但 E7 有同向失败警示。
> 代价：新一轮设计审查；多条冻结条款的解冻与重写；与真实数据源原则的张力需要正面解决。
> 风险：复制失败设计的问题漂移（E7）；即便过审，落地依赖自建障碍成分，比 P / C 形态离「真实任务分布」更远。

**选项三：两种形态并入一次设计审查**

> 代价：最高；直接违反复活评估止损线（本轮只做一轮改设计评估，第 0、4 节）。
> 风险：E7 记录的失败模式——「用户补充一个限制后，设计就整体朝新限制推到底」——两形态同时入场极可能触发再次整体推倒。

**选项四：维持终止**

> 代价：M2 继续没有可运行测量（但现象层有 U2、E4、E5 支持，设计规格完整）；反馈线冻结至复检触发条件出现（复活评估第 1.7 节）。
> 风险：无新增；全部证据保留。

> 选项一与选项二在逻辑上不互斥，但在止损线下只能择一先行；本文档不做推荐，决定权在用户。

## 8. 总体结论

> 1. 三线分工的现象层与最早的两方向失配框架（B1）及仓库记录的原始观察一致，没有发生方向偏移。
> 2. U2 支持按 P / C 形态复活；障碍 / 停止提议有现象层价值但不通过现行标准检验，不是现成替代方案；上下文三层提议已被成文设计吸收。
> 3. 唯一真实缺口是「停止 / 知止」一面，三个处理选项已列（第 6 节）；QQ 例子撤销并留更正记录。
