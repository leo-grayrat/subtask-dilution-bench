# 反馈分配线复活决定记录

日期：2026-08-26

状态：本文件只新增决定记录，不修改 design.md、revival-assessment.md、source-verification.md 或任何既有文件；不运行任何实验、模型或代理。

## 1. 决定

2026-08-26，用户批准反馈分配研究线复活：按 revival-assessment.md 的 TAC 方案（以 TheAgentCompany 为唯一素材来源、以操纵层为运行架构、仅 C 模块先行）推进，并批准第 2 节五个复活条件全部生效。本文件是该批准的记档。

## 2. 批准依据

### 2.1 原始现象动机

反馈线的立线现象与出生证明、用户一手例子一脉相承（记载见 research-ledger-motivation-alignment.md 第 1 节）：

- E4（README 更新一节）：未经授权 draft PR 与疯狂测 CI——「我还tm不会忘掉因为沙盒里面不能测试就想入非非忘记了做好之前不给开发者看 AI 垃圾而开始未经授权 draft PR 然后疯狂测 CI 甚至惊动仓库主人的那二十分钟」。
- E5（README 主要事实和观点 2）：「显著反馈导致资源失衡应单独研究：CI 红绿一类指标会持续告诉模型还没完成，可能把局部目标变成过强的优化对象」。
- B1/B2（出生证明转述）：两方向局部失配中的 over-allocation / fixation 一端（持续红绿循环上死磕），与「每一步局部合理、整体背离」的事故结构概括。
- U2（用户一手例子）：代码正确性的 CI 反馈一直在响，AI 一直在测，但最后整个方向是错的——响亮的反馈在错误的轴上，真正重要的轴没有反馈。

出生证明的原文不在仓库存档中（archive/failed-design/ 检索 0 命中，系用户外部会话记录提供），以上 B1/B2 均为转述；U2 为用户口述重述。记载出处与证据边界见 research-ledger-motivation-alignment.md 第 0、9 节。

### 2.2 例证库 32 条真实证据

2026-08-26 完成的现象例证库（phenomenon-evidence-v0.md）合计 32 条证据：第一、二类案例 22 条，第三类素材潜力环境条目 10 个。
形态分布：A 环境反馈吸住 10 条（45.5%）、B 约束未参与执行 3 条、C 评分者偏好替代 4 条、D 验证代理物化 3 条、E 目标泛化失败 2 条。
关键观察：完全诚实的代理同样被响亮反馈吸住（Lighthouse 循环、Coast Runners），与 design.md 「这不是 reward hacking benchmark」的定位一致；本线 2×2 主假设对应现象主形态，例证库提供的是现象真实性的外部证据。

## 3. 复活条件五条（全文引用）

以下全文引自 revival-assessment.md 第 3 节（原文：「五个条件（全部满足才启动，任何一条不满足即回到维持终止）」）：

> 1. 用户接受来源唯一：只用 TheAgentCompany，无第二来源；若要求稀释来源集中度，等 1.7 节复检触发条件或维持终止。
> 2. 仅 C 模块先行：P 模块待呈现器信息等价工程成熟后另行决策，本轮不启动。
> 3. 实测门槛逐题过：候选任务须同时通过 F、C 成分真实性审查与预算稀缺性预检；不通过即淘汰，不许事后补救，不许放宽标准。
> 4. 隔离前置：启动前须有实测通过的隔离方案，被测代理不可接触操纵层任何部分。
> 5. 停止规则全保留：预检不过即停止（design.md 第 12.2 节）、无信号不扩题、2.4 节不得声称清单全量生效。

用户同时批准四步最小落地路径（同节原文 1 至 4 步）及其回落条款：「以上四步任何一步不过，自动回落到维持终止，不做第二次挽救。」
五条件的执行口径在 tac-landing-plan-v0.md 中逐条落位：条件①对应来源锚与唯一性声明，条件②对应仅 C 模块的呈现器规格，条件③对应逐题实测门槛七项，条件④对应隔离前置项，条件⑤对应停止规则与不得声称清单。

## 4. 障碍-停止形态：经用户指示不再采用

明确记录：障碍-停止形态经用户指示不再采用，不再作为反馈分配线的选项。

该形态的记载见 research-ledger-motivation-alignment.md 第 3.1 节（候选方案转述）：在真实复杂任务上故意设置不可解的局部障碍加全局边界约束，观察模型何时意识到继续不划算；指标为 Obstacle overhead、Escalation depth、Constraint violation、Task displacement、Stop quality。
不再采用的记录依据（与动机对齐文档第 3.1 节结论一致）：该形态与现行冻结条款冲突——「故意不可解的局部障碍」违反反馈线 design.md 第 3 节「F、C 都必须是真实任务要求」「不能把一个本来无关的小游戏塞进任务充当诱饵」及其条件 6（不得长期处于接近全错的极端状态）；同时触碰稀释线「不添加逻辑陷阱」条款与研究总账原则 10；E7 失败记录对 CI 式反馈阶梯留有历史警示。
该形态所对应的「及时返回 / 知止」缺口仍如实登记在 research-ledger-motivation-alignment.md 第 6 节，本决定只关闭其作为本线选项，不关闭观察记录；未来如需重开，须另行设计审查，与本决定无关。
## 5. 替代关系

本决定替代 source-verification.md 第 4 节「建议触发停止规则，部分终止」的待决状态：该建议于 2026-08-25 提出时未获用户批准，一直处于待决；本决定批准复活后，「部分终止」处置不再执行。

被替代的只是处置建议的待决状态，不是核查事实。source-verification.md 的全部核查结论继续有效、不被本决定推翻：RHB 无公开可运行实现、EvilGenie 结构性四项（S2 / S3 / S5 / S6）不满足、两来源均从公开资料判不合格；第 5 节复检触发条件继续有效。
本决定同时是对 research-ledger-motivation-alignment.md 第 7 节选项集的执行：选定选项一（按 P / C 分配形态复活，本轮仅 C 模块）；选项二（按障碍-停止形态重设计）经用户指示关闭；选项三违反复活评估止损线，从未采纳；选项四（维持终止）被本批准替代。

## 6. 红线与边界

- 本决定不修改 design.md 410 行设计；设计全部保留，复活的只是该设计的执行许可与素材路线。
- 五个条件是启动的合取条件，任何一条不满足即回到维持终止，不设第二次挽救。
- 来源唯一意味着本线不启用第二来源；source-verification.md 的复检触发条件若将来满足，只恢复对应来源的复核资格，进入候选仍须另行设计审查。
- 本决定不含任何实测、运行或工程放行；隔离、Docker 服务栈、练习任务、模型配置等阻塞一项未动。

## 7. 本决定不得声称什么

- 不得声称本线已可开跑：纸面记档不等于验证、不等于冻结、不等于可开跑。
- 不得声称 P 模块结论：按条件②仅 C 模块先行，任何结论必须点明是「连续可优化性」，不能简称为整个反馈 benchmark（design.md 第 8 节、复活评估 2.4 节第 2 条）。
- 不得声称 8 个母任务已凑定：候补名单是纸面草案，正式有效数取决于逐题实测（见 tac-landing-plan-v0.md）。
- 不得声称例证库证明实验会得到预期结果：例证库只证明现象在真实世界中存在，不构成任何实验结果的先验。
