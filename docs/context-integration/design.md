# 上下文不参与决策：实验设计

## 研究问题

我们要验证一种比“忘了上下文”更窄的失败：

> **模型记得规则、知道规则如何作用于当前情况，单独让它实际处理这个局部问题时也能做对，但放回完整复杂任务后却做错。**

因此第一版不直接讨论模型内部机制，只验证这种行为现象是否稳定存在。

## 核心实验

对同一个局部决策，做四个彼此独立的测试，避免前一个测试提醒后一个。

1. **规则记忆**：给完整规则文本，确认模型能找出相关要求。
2. **规则应用**：直接给相关规则和当前情况，确认模型知道这个动作此时该不该做。
3. **局部执行**：只保留完成这个局部工作必要的环境，让模型真的调用工具完成，而不是只回答选择题。
4. **完整执行**：回到原始复杂任务，不提醒目标规则，观察它实际是否做对。

真正关注的情况是：前三项稳定正确，完整执行却失败。

## 数据来源

第一版只使用 **HANDBOOK.md**。

它已经提供完整工作任务、长期有效的规则、可操作环境和程序化评分，适合直接从真实任务中抽取局部决策。第一版不同时接入多套 benchmark，避免研究问题还没验证就先陷入环境适配。

每个样本必须在运行被测模型之前确定，不能根据某个模型已经犯过的错误回头挑题。

## 反向版本

每个局部决策尽量做成一对：

- 一个版本中规则确实生效，动作不应执行或必须执行；
- 另一个版本只改变一个关键事实，使规则的适用结果翻转。

这样不能靠“一律拒绝行动”或“一律执行”取得高分。

## 评价

第一版只报告容易理解的结果：

- 前三项中有多少局部决策已经证明模型会做；
- 这些已经证明会做的决策，进入完整任务后有多少失守；
- 局部执行与完整执行之间下降了多少。

同时保留原任务其他部分的得分，避免把“整个任务都不会”误判为我们关心的现象。

## 第一版要回答的问题

Pilot 不做排行榜，只回答：

> **是否稳定存在“规则记得、会应用、单独也会操作，但完整任务中却没有把它用上”的局部决策？**

如果这种情况有稳定信号，再扩大题库并用其他 benchmark 做外部验证；如果没有，就重新评估这一方向，而不是强行扩大。
