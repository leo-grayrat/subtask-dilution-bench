# 上下文不参与决策：实验设计

## 1. 研究问题

本方向只验证一种较窄的行为现象：

> **模型能从规则材料中找出相关要求，能判断该规则在当前事实下是否适用，单独处理这个局部工作时也能正确行动，但进入原始完整任务后却没有把这些信息用于行动。**

这不是对子任务稀释全部现象的定义，也不预先断言原因是注意力、记忆容量或推理资源不足。子任务稀释的 checkpoint fork、显著反馈导致资源失衡，仍是另外两条独立实验线。

## 2. 实验单位与 v0 范围

实验单位是一个来自真实完整任务的**母任务**，以及其中一个预先选定的规则—状态—行动关系。

v0 冻结为已经实现的 7 个 HANDBOOK 母任务：S01、S02、S04、S07、S08、S09、S10。每个母任务现有 A/B 两个事实状态，以及 Local/Full 两种执行条件。

因此：

- S01 的 4 个条件加上另外六题的 24 个条件，共 28 个执行条件；
- **28 个条件不是 28 个独立样本，而是 7 个母任务的重复测量；**
- A/B、Local/Full 和多次独立运行都不能被用来扩大“独立题目数”；
- 25 个候选池不属于 v0，不因看到某个模型的结果而临时加入。

## 3. 四层独立诊断

四层测试回答不同问题，必须由彼此独立的新会话运行。任何一层的提示、回答或轨迹都不能传给下一层。

### Recall：规则记忆

给被测模型完整的 SOP / policy 材料，要求它以固定格式找出与目标决定有关的规则。不提供目标任务的 A/B 当前状态，也不要求执行动作。

Recall 只验证规则能否从原材料中被取回。因为 A/B 改变的是业务事实而不是规则，同一母任务的 Recall 不人为复制成两个“不同样本”。

### Applicability：规则应用

给出相关规则和完成判断所需的最小当前状态，询问目标动作在该状态下应执行、不得执行，还是需要走另一条路径。A/B 使用镜像问题，正确结论必须随关键事实翻转。

这一层不调用工作工具，验证的是规则与当前事实能否正确结合。

### Local：局部执行

使用现有 Local A/B 任务包。保留完成目标局部工作所需的真实材料和工具，但把工作范围限定在该事项。评价实际环境状态和实际沟通，不把口头回答当作完成。

### Full：完整执行

使用现有 Full A/B 任务包。保留原始完整任务及其他工作，不提醒目标规则或目标局部，评价模型是否到达该决定、目标动作是否正确，以及完整任务其他部分完成得怎样。

当前代码和匿名包已经实现 Local 与 Full 的 A/B 条件；**Recall 和 Applicability 尚未实现。** 在补齐并独立运行这两层之前，现有结果最多能说明“局部执行与完整执行不同”，不能证明“模型记得、理解、局部会做，却在完整任务中没用上”。

## 4. A/B 反事实对照

每个母任务的 A/B 只改变一个有业务意义的关键事实；如果该事实同时出现在邮件、附件和表格中，可以同步修改这些重复表示，但不得顺便改变第二个决定条件。

A/B 的正确行动必须真正翻转。它用于排除以下固定套路：

- 一律拒绝或暂停；
- 一律执行；
- 一律升级；
- 只复述规则，不根据当前状态作决定。

若修改后还有第二个独立条件阻止行动，或来源规则与评分器冲突，该版本不能进入冻结运行。现有 `quality-audit.md` 中的降级记录继续保留，不能为了补数量恢复进 v0。

## 5. 独立运行与隔离

被测模型不能看到本仓库、测试、评分器、私下条件表、题号或实验目的。有效运行至少满足：

1. 每次运行使用新的独立会话和新的临时目录；
2. 临时目录位于本仓库之外，只解压一个匿名任务包；
3. 新会话不继承实验员对话、前一道题的对话、答案或运行结果；
4. 只改变预先冻结的模型配置、条件和随机种子，不在失败后追加提醒；
5. 评分由实验员在运行结束后于仓库侧完成；
6. 仅仅更换工作目录不算语义隔离；若无法证明会话不继承主对话，实验不得开始。

Recall、Applicability 也要匿名导出，并遵守相同的独立会话原则。它们不能在 Local 或 Full 之前由同一被测会话先做一遍。

## 6. 评价与统计单位

每次运行分别记录：

- Recall 是否正确；
- Applicability 是否正确；
- Local 目标行动是否正确；
- Full 是否到达目标决定；
- 到达后目标行动是否正确；
- Full 原任务其他部分的得分。

我们关心的运行模式是 `Recall = 对、Applicability = 对、Local = 对、Full = 错`。Full 未到达目标决定时单列为“未到达”，不能算对，也不能算错。

统计时以母任务为组：

- 先在每个母任务、每个 A/B 状态内汇总重复运行；
- 再比较 Local 与 Full 的差值；
- 7 个母任务等权报告，不让运行次数多的题占更大权重；
- 同时给出逐母任务结果和逐一移除一个母任务后的敏感性结果；
- 如给区间，只能按母任务整组重采样，并明确 7 个组的区间会很宽。

不能把 28 个条件或其重复运行当成互相独立的 `n`。v0 不追求一个排行榜总分，也不把四层硬合成一个神奇分数。

## 7. 结论边界

即使 v0 出现稳定信号，也只能得出：

> 在这 7 个经过人工筛选的 HANDBOOK 母任务、指定模型和指定运行配置下，观察到了符合四层定义的上下文整合失守。

它不能单独证明：

- 所有 AI 或所有复杂任务都有这种现象；
- 内部原因一定是“注意力被摊薄”；
- HANDBOOK 规则任务能代表代码、研究、写作等领域；
- 题目变体和重复运行等于更多独立任务；
- 某模型因此具有更高或更低的总体智能。

若没有信号，也只能说明 v0 没有抓到稳定现象，不能证明该现象在其他任务中不存在。

## 8. 冻结与停止原则

运行前冻结母任务名单、A/B 事实、四层提示、评分规则、模型配置、重复次数、种子和任务包校验值。发现材料或评分错误时，应给受影响样本升版本并使旧结果失效，不能在原结果上悄悄修答案。

v0 完成预先规定的运行后即停止，不通过继续搜索新题来“补出”信号：

- 隔离无法成立：停止运行；
- Recall、Applicability 或 Local 普遍失败：说明前置能力没有建立，停止把 Full 失败解释为本现象；
- 信号只来自一个母任务：按个案报告，不扩写成稳定 benchmark 结论；
- 多个母任务出现同方向结果：可以进入下一阶段设计评审，但不能自动授权继续扩题。
