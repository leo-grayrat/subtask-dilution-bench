# 正式模型实验前检查

更新日期：2026-08-25

这份清单回答两个问题：现在仓库里已经有什么，开始正式模型实验前还缺什么。它不把工程测试通过写成模型实验成功。

状态含义：

- **已完成**：当前仓库中有可核对的设计、实现或检查记录；
- **部分完成**：已有一部分，但还不能满足正式运行门槛；
- **未完成**：仓库中没有可确认的完成证据，或已有文档明确写着尚未完成；
- **待选择**：存在两个合理分支，必须在运行目标模型前选定并冻结。

只有“共同门槛”全部满足，并且对应研究线自己的门槛全部满足，该研究线才可开始计入结果的模型实验。三条线互相独立，不要求一起等待；一条线就绪不能替另一条线放行。不计分的可行性测试也必须使用无实验内容的练习任务，不能先拿正式任务调通流程。

## 5. 必须保留的重大分支

这些选择不需要今天强行拍板，但必须在相关正式运行前明确选择、写入 manifest 并冻结：

1. **子任务稀释如何分叉**：真实状态复制；或经验证的可见状态重建。若两者均不可行，独立整题运行只能作为辅助证据，不能悄悄替代主实验。
2. **子任务软性结果如何报告**：具备独立人类盲评时进入正式软结果；否则只报告硬结果，并把软性发现留作探索。
3. **反馈线的素材是否适配**：RHB / EvilGenie 中有合格任务则继续；没有则停止该 pilot。启用新来源属于新的设计审查，不是自动下一步。
4. **P/C 是否能共用同一批母任务**：能共用时形成同题多角度测量；只能支持一个模块时按窄模块命名，不能把另一模块算作已测。
5. **独立运行方式**：独立 Codex 会话、独立 CLI 进程或其他可证明不继承实验语义的方式均可；选择依据是验证证据，不是名称。若都无法证明，三条线都不能开始正式运行。

上下文整合不再保留“直接用 Local/Full 冒充四层”的分支。v0 已选择补齐 Recall 与 Applicability 后再做正式四层诊断；现有四层材料目前只用于工程验证，正式结论仍需真实隔离下的模型运行。

## 6. 可以开始正式运行的判定

某条研究线只有同时满足以下条件才算就绪：

- 共同门槛中所有“未完成”和“正式阻塞”已经关闭；
- 该线正式母任务、条件、提示、评分、重复、预算和停止规则有带 SHA-256 的冻结清单；
- 匿名包经过自动扫描和人工抽查；
- 无实验内容的独立运行已走通启动、隔离、产物回收和评分；
- 所有重大分支已有明确选择，且没有根据目标模型结果事后选择；
- 首次正式运行前保存 manifest 的冻结版本和校验值。

截至本文件日期，三条研究线都还没有达到这个状态。上下文整合的四层材料工程已完成（含 2026-08-25 完整工程测试 123 项通过），但仍被真正的隔离、模型配置冻结、二进制规则包人工抽查和逐题到达判定阻塞；另外两条线仍处在正式母任务与运行实现之前。
