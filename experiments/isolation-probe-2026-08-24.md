# 2026-08-24 独立运行隔离探针

## 这是什么

这是一个不计分的基础设施检查，不是 S01，也不是三条研究线中的模型实验。检查使用空白临时目录和普通提示，不提供任何正式任务材料，不产生研究分数，也不能支持模型行为结论。

检查只回答两个问题：新的 Codex 进程是否继承实验员对话，以及它能否越过临时工作目录读取本仓库。

## 实际检查

### 1. 普通独立 CLI 进程

从仓库外的临时目录启动全新的 `codex exec`，没有使用 `resume`。启动时要求：

- 会话不落盘；
- 不加载用户配置和命令规则；
- 关闭 memories 的读取与生成；
- 不允许申请额外权限；
- 只把临时目录设为工作目录。

当前主对话事先放入语义暗号 `青铜风铃-5821`。新进程被要求在不查文件的情况下写出继承到的暗号，否则回答 `UNKNOWN`；同时只尝试读取本仓库 `README.md` 的第一行。

结果：

- 对话：回答 `UNKNOWN`，没有显示出继承当前主对话；
- 文件：成功读到 `# subtask-dilution-bench`；
- 启动日志：虽然设置了“不加载用户配置”，仍扫描了用户目录中的插件和技能。

因此，新进程和新工作目录只能初步解决对话继承，不能证明“只看匿名任务目录”。这一方式不合格，不能用于正式运行。

### 2. Codex 文件权限配置

本机 CLI 版本为 `0.137.0`。随后用不启动模型的命令检查两种文件权限规则：

- 默认拒绝读取整个磁盘，只重新开放运行工具所需的最小路径和当前工作目录；
- 直接拒绝读取 `D:\File\Git\subtask-dilution-bench`。

较弱的 Windows 后端明确表示不能执行这种读权限隔离。较强后端能够启动，但上述两条规则下仍然读到了仓库第一行，所以本机当前组合没有通过实测。

官方文档说明，新的 permission profile 可以按路径限制读写，并给出了“默认拒绝磁盘读取、只开放工作区”的配置；同时也把它标为仍在变化的 beta 功能。Windows 上需要较强后端才能可靠执行拆分的读写限制：[Permissions](https://learn.chatgpt.com/docs/permissions)、[Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)。本项目以本机实测为准，不因文档声称支持就判定隔离成功。

## 当前结论

本次探针排除了两种说法：

1. 只要启动新的 subagent 或 CLI 进程就算隔离；
2. 只要更换工作目录并使用普通 `workspace-write` 就看不到其他仓库。

当前没有通过隔离门槛。不得用上述命令运行 S01 或任何正式任务，也不得生成分数。

后续只有以下任一方案经过同样的无实验内容检查，才可以放行：

- 在不改动全局安装的前提下，另行测试支持严格 permission profile 的 CLI 版本；
- 使用单独的 Windows 账户、容器、WSL 或云环境，并且只挂载一个匿名任务目录；
- 采用其他能由外部文件探针证明“仓库不可读”的执行环境。

本机当前没有可用的 Docker / Podman，也没有已安装的 WSL 发行版。安装或升级全局工具属于单独的系统选择，本次没有擅自执行。

## 将来怎样才算通过

新的隔离方式必须先在普通练习任务上同时满足：

- 不知道主对话中的随机暗号；
- 能正常读取和修改匿名任务目录；
- 无法读取 benchmark 仓库、测试、评分器、私下对应表和实验员记录；
- 不加载用户 memories、插件、技能或项目说明；
- 能回收产物并在主进程中完成一次不计分的评分演练；
- 每个被测实例均为新的独立会话，不使用 `resume`，不同任务之间不共享上下文。

在这些条件全部留下可复核证据以前，隔离状态保持“未完成，正式阻塞”。
